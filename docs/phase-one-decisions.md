## D02：课程视频

采用受控媒体资源配合原生播放器。理由：可以明确管理视频来源和可用性，并接收播放器的播放、暂停、进度和结束事件；减少对第三方网页跳转权限与合作接口的依赖。Taro第一方Video接口声明支持资源地址及相关事件，微信端具体账号、域名和设备仍需独立验证。[Taro Video接口源码](https://raw.githubusercontent.com/NervJS/taro/main/packages/taro-components/types/Video.d.ts)

首期内容分为：

- 本地开发/自动化：使用自行制作的测试片或自有测试素材，显著标为测试资源；模拟课程不能冒充正式课程，不把原型共用B站片源当全部课程。
- 正式课程：后台记录媒体地址、来源、作者、授权说明、时长与发布状态。没有经过授权确认的资源不得作为正式可播放课程发布；不下载、搬运B站课程。
- 没有可用媒体：展示待配置/不可播放状态，核心API和推荐流程仍可测试；不默认跳转到无关视频。

**2026-10-18用户补充的课程时长规则：**取消原有时长/类型筛选，正式产品只提供实际总时长不超过35分钟的课程，35分钟整包含在内；不再提供“1–3分钟/约30分钟”或“短视频/系统课程”筛选按钮。卡片展示实际时长，不因课程类型排除35分钟以内的内容。场景、任务、等级关联及来源授权要求照常适用。

统一判据为`0 < durationSeconds <= 2100`。一门课程以实际总时长判定，不按某个章节单独计算，不把超过上限的时长四舍五入成35:00放行。未知/无效时长或超长课程可保留草稿，但不能正式发布、进入推荐或通过直接详情入口绕过限制；不自动剪辑或拆分原视频。后台发布校验、API、前台显示和测试使用同一判据。原型文件保留原筛选作为历史设计，不随本次决定改动。

播放器进度是“客户端报告的播放位置”，不等同于已经学会。首期分别存：最后播放位置、播放器结束事件、用户手动看过标记。拖动到末尾不能据此推出真实学习时长；暂不产生“认证完课率”。来源网页不能填入视频资源字段，视频URL须通过发布校验；服务端不任意代理外部URL，避免把媒体处理变成开放代理。

本决定不包含对象存储采购、上传用户私人课程、公开分发、云带宽开通或备案/发布动作。原有原型外链行为原样保留，正式工程按此新决定实现。

## D03与D06：无登录的记录隔离

不调用`wx.login`，不制作登录页、不收集手机号、不连接百年前程账号。首次使用时API自动创建匿名访客，返回服务端生成的不可预测访客凭据，客户端保存在本机存储；后续API由该凭据确定记录归属，不接受请求体中的任意ownerId。

这是访客数据访问控制，不是微信或平台登录。清除本机存储、换设备或重装后，不能保证找回原访客记录或跨端同步；界面及说明应如实呈现此限制。凭据不进入埋点与日志。

- 学习计划唯一键：`visitorId + sceneId + taskId`，同一键幂等；不同任务互不覆盖。
- 每个任务独立：测验尝试、题目快照、推荐等级、自主等级、继续学习位置。
- 同一课程的手动看过标记：`visitorId + courseId`；各任务从自己的课程关联中计算展示，不重复创建课程标记。
- 测验历史按attempt保存；换任务、重测、题库更新均不覆盖旧attempt。

实现术语澄清：结合[产品手册第5节](../小程序产品开发说明手册.md)，上述任务“继续学习位置”表示该任务最近访问的课程入口；同访客的同一课程播放秒数和手动看过共享。任务测验/等级不共享。此处细化既有手册口径，不增加每任务同课从头计时的新规则。

本地首期后台也不增加登录流程，只在本机回环地址开放，管理API与前台来源约束分别处理。D08未决定前不开放公网；上线前另行决定管理员访问控制及用户身份，不能把本地免登录管理接口直接部署到公网。当前检查仅证明有Docker客户端，Docker引擎未运行，尚不能验证MySQL联调。

## D07：事件和分析的固定口径

### 标识与时间

- 时间存储UTC；报表自然日、D1、D7按`Asia/Shanghai`。
- visitorId代表一台本地安装环境的匿名访客，不代表已经验证的自然人；目前没有账号合并或跨设备识别。
- session在连续30分钟无操作后更新；午夜不强行切session。session不是安全凭据，不决定数据访问权限。
- flowId代表一次岗位/任务学习流程；同一流程中taskId区分多任务，防止把不同任务的步骤拼成成功漏斗。

### 事件与漏斗

最小事件：`page_view`、`jd_submit`、`ocr_result_confirmed`、`analysis_completed`、`scene_selected`、`task_selected`、`assessment_started`、`assessment_submitted`、`level_changed`、`recommendation_viewed`、`course_detail_viewed`、`course_open_attempted`、`video_started`、`video_paused`、`video_progress`、`video_ended`、`course_mark_changed`、`learning_plan_resumed`。

- 页面曝光不作为学习活跃。DAU取当天发生任务选择、测验开始/提交、课程打开、有效学习恢复或看过标记变化的visitor去重数；同日重复操作只记一个活跃访客。
- D1/D7：在某日首次产生上述学习活跃的访客，分别于次日/第7日再次产生学习活跃的比例；按自然日，不用“过去24小时”代替；未到观察日不计为流失。
- 岗位漏斗：提交JD→分析成功→选择任务→提交测验→推荐曝光→打开课程。任务漏斗：选择任务→提交测验→推荐曝光→打开课程。24小时窗口，按`visitorId + flowId + taskId`校验有序事件，再计算链路数及访客去重数；岗位分析是flow级事件，可关联该flow下的任务，不串其他flow。日漏斗以入口发生日归属，跨日完成归回入口日。
- 打开课程、播放器开始/结束、手动看过分别计数；不能把打开率、拖到末尾或手动标记率直接命名为完课率。
- 测验提交成功、分析完成由服务端业务事务确认，客户端不能自行制造这些权威成功事件。客户端与服务端同名事件只保留一个权威来源。

### 采集、去重和保留期

- 请求层记录requestId、路由模板、状态码、业务错误码、耗时、重试次数及环境；客户端输入的关联ID须限制长度/格式。无请求正文、图片、token、IP长期追踪或JD原文。
- 行为事件按eventId去重，记录occurredAt和receivedAt。每批最多50条，本地未发送队列最多200条、24小时过期，退避重试；上报失败不阻断学习。
- `video_progress`最多每15秒发送一次，暂停/结束可补发；去重和异常跳跃校验，客户端位置不作为可信学习时长。
- 原始行为事件保留90天，接口明细14天，日聚合365天；学习业务记录与管理员发布审计不套用埋点保留期。截图默认处理结束后24小时内清理原文件，失败任务同样清理；确认文本按用户学习业务记录处理，不能写入通用日志。
- `local/test/demo`数据独立过滤，正式分析默认排除；模拟数据不得出现在生产留存报表。
- 客户端occurredAt超出接收时间±24小时则标记时钟异常，以receivedAt用于运营分桶；不让客户端任意改写历史统计。未来离线超过24小时的补报协议另行评估。

以上为首期工程默认值，不宣称已经完成法律审查或公开上线授权；当前未采集真实用户数据。
